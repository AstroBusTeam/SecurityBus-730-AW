## Capítulo III: Requirements Specification

### 3.1. User Stories

En esta sección se presentan las 50 User Stories que conforman los requerimientos del sistema **SecurityBus**, organizadas por épica. Cada historia incluye su identificador, título, descripción en formato _Como / Desea / Para_, sus criterios de aceptación expresados en notación Gherkin (_Given / When / Then_) con escenarios de éxito y de fracaso, y la épica a la que pertenece.

**Épicas del proyecto:**

| Epic ID | Título                             | Descripción                                                                                                                                                                                    |
| :------ | :--------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EPNN01  | Gestión de conductores y servicios | Agrupa las historias relacionadas con la validación de identidad del conductor, su autorización, la asociación conductor–vehículo y el ciclo de vida del servicio (inicio, consulta y cierre). |
| EPNN02  | Gestión de alertas de emergencia   | Agrupa las historias relacionadas con la generación, envío, recepción, clasificación, escalamiento y registro de alertas de emergencia.                                                        |
| EPNN03  | Monitoreo de pasajeros y ocupación | Agrupa las historias relacionadas con el conteo automático de pasajeros, la detección de sobrecapacidad y el análisis de la ocupación de las unidades.                                         |
| EPNN04  | Landing Page informativa           | Agrupa las historias del visitante orientadas a conocer la problemática, la propuesta de valor, las funcionalidades, los beneficios y la identidad de la startup.                              |
| EPNN05  | Web Services / API                 | Agrupa las historias del developer orientadas al consumo de los endpoints del sistema para validación, registro, consulta y administración de recursos.                                        |
